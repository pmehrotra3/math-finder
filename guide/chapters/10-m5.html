M5: From LaTeX to a Lean statement you approve

What and why. People write theorems in LaTeX, but Lean needs an exact formal statement. Translating is the most dangerous step in the whole system, because Lean will happily prove a statement that doesn't say what you meant. Two classic traps: on the natural numbers ℕ, 2 - 5 = 0 (subtraction stops at zero), and dropping an assumption like "n ≥ 1" quietly changes the claim. A perfect proof of the wrong statement is worthless. So we check three ways and then ask you:

  1. Lean must accept the statement (it type-checks, with sorry as the proof). If not, the error goes back to the model to fix.
  2. A separate model call translates the Lean back into LaTeX without seeing your original, so it can't "helpfully" paper over a mistranslation.
  3. A judge compares your LaTeX with that back-translation, looking specifically for the classic traps.
  4. You approve, reject, or edit the Lean statement yourself. Nothing is searched until you say yes.

  1. Create the formalizer.

    {{file:mathfinder/formalize.py}}

    Three system prompts, three jobs. SYSTEM_FORMALIZE spells out the traps (ℕ subtraction, missing hypotheses) and the exact output format. SYSTEM_BACK says literally and "do not fix anything", because a back-translator that guesses intent would hide errors. SYSTEM_JUDGE gets a checklist of what to compare.

    @property makes ok read like a field (result.ok, no parentheses) while actually computing it from statement and errors.

    clean_statement forgives answers like theorem foo (n : ℕ) : ... := by sorry: it strips the keyword, the name (unless the text right after the keyword already starts with a binder or a colon) and everything from := on. text.split(None, 1) splits once at the first run of whitespace.

    formalize has the same shape as the prover's repair loop: ask, check with Lean, and on failure append the statement and Lean's error to the prompt and ask again. verdict.get("same_meaning") is True counts only a real JSON true as yes; a vague answer counts as no.

  2. Create its tests.

    {{file:tests/test_formalize.py}}

    @pytest.mark.parametrize runs one test function once per row of inputs: five clean_statement cases in five lines. The scripted Lean test makes the "model" give a broken statement first (undefined_q), so the repair path really runs against Lean. It also asserts that the back-translator's prompt doesn't contain the original. The last real test feeds the judge an ℕ-vs-ℤ trap and expects "not the same".

  3. Add the approval step to the command line. Replace the whole file:

    {{file:mathfinder/cli.py@m5}}

    What changed: prove now takes the theorem in LaTeX as a positional argument (nargs="?" makes it optional, because --lean still works and skips formalization). There's a new --yes flag, and a new function approve.

    approve prints the formal statement, the back-translation and the judge's verdict, then loops on [y]es / [n]o / [e]dit. An edited statement is checked by Lean before it replaces the old one. --yes is honoured only when the judge agrees: if it thinks the meaning may differ, you're asked anyway. ask=input is a default argument holding a function: normally it's Python's input, and tests pass a scripted user instead. except EOFError handles running with no keyboard (in a script), which counts as "no".

    scripted_user("e", "(n : ℤ) : oops", "e", ..., "y") plays a person who edits once badly (Lean rejects it), edits again correctly, then approves. These tests fake both formalize and Lean, so they're instant.

  5. Run the fast tests, then the real formalization tests (about 30 s of Claude):

    uv run pytest -q -m "not lean and not llm"
uv run pytest -q -m llm tests/test_formalize.py

  6. Prove a theorem written in LaTeX. Use single quotes so your shell leaves $ and \ alone:

    uv run python -m mathfinder prove 'For all positive reals $a, b$: $\frac{a}{b} + \frac{b}{a} \ge 2$.'

✓ VERIFIED by Lean. ...

theorem diff_identity (a b : ℝ) (ha : 0 < a) (hb : 0 < b) : a / b + b / a - 2 = (a - b) ^ 2 / (a * b) := by
  have ha' : a ≠ 0 := ne_of_gt ha
  have hb' : b ≠ 0 := ne_of_gt hb
  field_simp
  ring
...
Result: PROVED (verified)

Notice the formalizer turned "positive reals" into two explicit hypotheses ha : 0 < a and hb : 0 < b. Without them, a / b with b = 0 is 0 in Lean and the statement would be false.

Common errors

  • The LaTeX arrives mangled ($a disappears): you used double quotes, and your shell expanded $a as a variable. Use single quotes.
  • Could not produce a statement Lean accepts: unusual notation. Simplify the LaTeX, or write the Lean yourself and use --lean.
  • The judge says MEANING MAY DIFFER: read its reason. It's usually right (ℕ vs ℤ, a missing hypothesis). Choose e and fix the statement.
