M8: Remember everything, then turn it into training data

What and why. Every search produces valuable information: proofs Lean accepted, proofs Lean rejected (with the exact error), lemmas that turned out easy, false or stuck, and hints people gave. Systems like AlphaProof improved by training on exactly this kind of record of their own search. This chapter keeps it. A trace logger writes every event of every run to runs/<id>/trace.jsonl, failed attempts included, and mathfinder export turns all traces into four datasets:

FileOne row isTrains
sft.jsonlgoal (+ lemmas it may use) → a proof Lean acceptedthe prover to imitate good proofs ("supervised fine-tuning")
preferences.jsonlsame goal: a proof that worked vs. one that failed (+ its error)the prover to prefer what works (e.g. DPO)
value.jsonllemma statement → proved / refuted / stucka value model that guesses how hard a goal is, so search can try promising plans first
hints.jsonlthe hints a person gave → whether it got provedlearning which advice actually helps

  2. Make the prover report every attempt. Replace the whole file:

    {{file:mathfinder/prover.py}}

    What changed: prove_lemma takes on_attempt=None. Inside it, a small helper report(...) builds one record per attempt: the goal, the lemmas it could use (context), the proof, whether Lean accepted it, Lean's error, and where it came from (hammer, llm or repair). It's called for the hammer's winning tactic and, through try_proofs, for every LLM attempt.

    try_proofs now goes through all attempts instead of returning at the first success. Lean already checked them all in one run, so this costs nothing, and a failure sitting next to a success on the same goal is exactly a preference pair. We found this in a real run where preferences came out as 0.

    lambda p, ok, e: report(p, ok, e, source) adapts report (4 arguments) to what try_proofs calls (3 arguments), filling in source from the current round.

  6. Create the trace module.

    {{file:mathfinder/traces.py@m8}}

    JSON Lines (.jsonl) is one JSON object per line. You can append to it without reading it first, and a crash mid-run loses at most one line. open("a") opens a file for appending. with self._lock, self.path.open("a") as f: uses two context managers in one with: hold the lock and keep the file open, then release both.

    TraceLogger has a __call__ method, so a logger object can be called like a function: logger(event). That means it can be used directly as an on_event callback. chain makes one callback out of several, so one search can be printed and logged.

    records_from_trace turns one run's events into dataset rows. For preferences it groups attempts by goal (dict.setdefault(key, []).append(...) creates the list the first time a goal appears) and pairs every success with every failure. export removes duplicate rows by using each row's JSON text (with sort_keys=True, so key order doesn't matter) as a dictionary key.

Common errors

  • export shows all zeros: no runs/*/trace.jsonl files yet. Runs from before this chapter have no trace; prove something new.
  • json.decoder.JSONDecodeError reading a trace: a run was killed mid-write. Delete that run's last (broken) line, or the folder.
  • TypeError: fake_prove() got an unexpected keyword argument 'on_attempt': a test fake needs on_attempt=None (step 5).
