M0: Project skeleton

What and why. Before any math, we set up the Python package, a test runner, and the tool that builds this guide. Every later chapter adds one module and one test file, so having tests run from day one means you always know whether things still work.

  1. Create the Python project file at the project root.

    {{file:pyproject.toml@m0}}

    [project] names the package and lists runtime dependencies (just the anthropic SDK for now). [dependency-groups] dev holds tools only needed while developing (pytest). [build-system] tells uv how to install our own package so that import mathfinder works everywhere. The pytest section registers an llm marker and skips those tests by default (-m 'not llm'), because they are slow and use your Claude quota.

  2. Create the package's first file.

    {{file:mathfinder/__init__.py}}

    A folder with an __init__.py is a Python package. Path(__file__) is this file's location; .resolve().parent.parent walks up to the project root. Every module will use LEAN_DIR to find the Lean project, so no path is hard-coded twice.

  3. Create a .gitignore so generated and heavy folders are never committed.

    {{file:.gitignore@m0}}

    lean_env/.lake/ holds the multi-GB Mathlib download; runs/ will hold search logs.

  4. Create the first tests.

    {{file:tests/test_smoke.py}}

    pytest runs every function whose name starts with test_. assert fails the test if the condition is false. shutil.which("lake") returns the path of the lake command, or None if it isn't installed.

  5. Create the virtual environment and install everything.

    uv sync

    This reads pyproject.toml, creates .venv/, installs the dependencies, and writes uv.lock (exact versions, so the setup can be reproduced later).

  6. Create the guide builder. (This is tooling for the guide itself; you don't need to understand it to build Math Finder.)

    {{file:tools/build_guide.py}}

    It reads guide/template.html and every guide/chapters/*.html file, and replaces each {{file:...}} tag with the real contents of that file. A regular expression (re.compile(...)) finds those tags. html.escape makes characters like < show up as text instead of being read as HTML.

  7. Add a test that fails whenever the guide is out of date with the code.

    {{file:tests/test_guide.py}}

    importlib loads tools/build_guide.py as a module even though tools/ isn't a package. The test rebuilds the guide in memory and compares it to guide.html on disk.

    You only need tools/build_guide.py and this test if you also want to rebuild the guide. They're always shown in their latest version.

  8. Build the guide.

    uv run python tools/build_guide.py

Checkpoint

uv run pytest -q

Expected:

....                                                                     [100%]
4 passed in 0.05s

Common errors

  • ModuleNotFoundError: No module named 'mathfinder': run tests with uv run pytest, not plain pytest, and rerun uv sync.
  • test_guide_is_up_to_date fails: you changed a file; rebuild with uv run python tools/build_guide.py.
  • test_lake_is_installed fails: go back to Chapter 0, step 2.
