M9: The web server

What and why. The website (M10) runs in your browser and can't call Python functions directly. It talks to a server over the network. This chapter puts the whole engine behind one, in two kinds of connection:

  • REST endpoints (plain HTTP requests, like loading a web page): "formalize this LaTeX", "start a search", "add this hint", "pause". Each request gets one reply.
  • A WebSocket: a connection that stays open, so the server can push every search event to the page the moment it happens (plan proposed, lemma proved, question for you) without the page asking over and over.

New ideas in this chapter

  • FastAPI is a Python web framework. You write a normal function and put @app.post("/api/check") above it, and FastAPI calls it for every POST request to that address, turning the returned dictionary into JSON.
  • pydantic models (class CheckRequest(BaseModel)) describe what a request body must look like. FastAPI checks every request against them and replies 422 by itself if something's missing or the wrong type.
  • async / await: an async def function can pause at each await (say, while waiting for the next event) and let the server work on other connections in the meantime. One thread (the event loop) juggles many WebSockets this way. uvicorn is the program that runs the event loop and our app.
  • Two worlds meeting: our search is slow, blocking code (Lean, the model), so it runs in ordinary threads, while the WebSockets live in the event loop. An asyncio.Queue may only be touched from its own event loop, so the search thread uses loop.call_soon_threadsafe(q.put_nowait, event), which means "event loop, please put this in the queue yourself".

  4. Create the server.

    {{file:server/app.py@m9}}

    import mathfinder.search as engine: we import the module and call engine.search(...) rather than importing the function. Tests can then swap in a fake with monkeypatch.setattr(srv.engine, "search", fake).

    Run is one search in progress. on_event is called from the search thread. It logs the event, appends it to events (the history, so a page that connects late can catch up), and hands it to every open WebSocket's queue. subscribe takes the history and registers the new listener under one lock, so an event arriving at that exact moment is neither missed nor sent twice. _work runs the search, writes the explanation, saves the run, and always ends with a finished event, even after a crash, so the page never waits forever.

    Plain def endpoints like formalize do slow blocking work. FastAPI runs those in a worker thread, so they don't freeze the event loop. Only watch is async, because it spends its life waiting.

    HTTPException(status_code=404) sends an HTTP error code instead of a normal reply: 404 means "no such session", 400 means "bad request". edit checks the new statement with Lean first, stops the old search, and starts a new one that keeps your hints.

    watch is the WebSocket endpoint. It accepts the connection, replays the history, then loops on await q.get(), sending each event with send_json until finished, and then closes. WebSocketDisconnect means the browser went away, and finally: run.unsubscribe(q) stops sending to it.

  7. Run the tests:

    uv run pytest -q -m "not lean and not llm"

  8. Start the server in its own terminal window and leave it running:

    uv run uvicorn server.app:app --port 8765

    server.app:app means "the variable app in the module server.app". We use port 8765 because 8000, the usual default, is often taken by another program.

  9. In a second terminal, formalize a theorem over HTTP with curl:

    curl -s -X POST localhost:8765/api/formalize -H 'Content-Type: application/json' \
  -d '{"latex": "For every natural number $n$, $n^2 + n$ is even."}' | python3 -m json.tool

  10. Start a search, send it a hint, and watch it live:

    ID=$(curl -s -X POST localhost:8765/api/sessions -H 'Content-Type: application/json' \
  -d '{"statement": "(n : ℕ) : Even (n ^ 2 + n)", "latex": "For every natural number $n$, $n^2 + n$ is even."}' \
  | python3 -c "import sys,json; print(json.load(sys.stdin)['id'])")
curl -s -X POST localhost:8765/api/sessions/$ID/hint -H 'Content-Type: application/json' \
  -d '{"text": "n^2 + n = n * (n + 1), a product of consecutive numbers"}'
uv run python tools/watch.py $ID

    ID=$(...) stores a command's output in a shell variable, and $ID uses it.

Common errors

  • [Errno 48] ... address already in use: another program has that port. Pick another (--port 8766) and use it everywhere.
  • {"detail":"Method Not Allowed"} from curl: you reached a different program on that port, or forgot -X POST.
  • {"detail":[{"type":"missing",...}]} (status 422): the JSON body is missing a field. Compare it with the pydantic model.
  • ModuleNotFoundError: No module named 'server' in tests: pythonpath = ["."] is missing from pyproject.toml.
  • The watcher exits right away: the session id is wrong (the server closes unknown ids with code 4404).
