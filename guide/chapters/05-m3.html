M3: Talking to Claude

What and why. The planner, the prover and the explainer all need to ask Claude questions. This chapter writes one small module, llm.py, with one function that matters: complete(system, prompt), which sends a question and returns the answer text. Behind it are two interchangeable backends: the claude command line tool (uses your Claude subscription, no key needed) and the Anthropic API (needs an API key). You switch between them with an environment variable, a named setting your terminal passes to every program it starts.

Two words you'll see

  • System prompt: standing instructions for the model ("You are a Lean 4 expert. Answer with JSON only.").
  • Prompt: the actual question for this call.

  1. Create the module.

    {{file:mathfinder/llm.py}}

    complete_cli runs claude -p ("print mode": answer once and exit) with subprocess.run. The prompt goes in on stdin (input=prompt) rather than as a command argument, because arguments have a length limit and prompts with Lean code can be long. --tools "" means Claude can only write text, not run commands. cwd=tempfile.gettempdir() runs it from a neutral folder so your project's files don't get mixed into the conversation.

    LLMError is our own exception class. raise LLMError(...) stops the current function and travels up until some caller handles it with try/except. Later the search catches it, so one failed call doesn't crash a whole proof attempt.

    complete_api uses the official SDK. with ... stream(...) as stream: is a context manager: the connection is opened at with and closed automatically at the end of the block, even on errors. We stream (receive the answer in pieces) because long answers would otherwise hit HTTP timeouts, and get_final_message() waits for all the pieces and returns the full message. effort: "high" asks for careful reasoning. fallbacks="default" (with its beta flag) means that if a safety check declines the request, the server retries it on a fallback model. We still check stop_reason == "refusal" in case everything declined.

    get_client creates the client once and stores it in a module-level variable (global _client). The import anthropic inside it means the CLI backend works without the API being set up.

    BACKENDS is a dictionary from name to function. complete looks up MATHFINDER_LLM (default "cli") and calls that function. Tests add a fake backend to this dictionary, which is why every other module calls llm.complete instead of picking a backend itself.

    extract_json: models often wrap JSON in a ```json fence or add a sentence around it. The regular expression ```(?:json)?\s*\n(.*?)\n``` captures the text between fences; re.DOTALL lets . match newlines too. Without a fence we take everything from the first { or [ to the last matching bracket. complete_json retries once, showing the model its parse error.

  2. Create the tests.

    {{file:tests/test_llm.py}}

    monkeypatch is a built-in pytest fixture that changes something just for one test and undoes it afterwards: setitem adds our fake backend to BACKENDS, setenv sets the environment variable, and setattr(llm, "_client", ...) swaps in a fake API client.

    SimpleNamespace makes a quick object with whatever attributes you give it, so fake_client(...).beta.messages.stream(...) works without a real SDK client. FakeStream implements __enter__/__exit__, the two methods that make a class usable in a with statement. The fake records the keyword arguments it receives, so the test can check we send exactly the request we mean to, with no key and no network.

  3. Run the fast tests. From now on, use this combined filter for "fast only":

    uv run pytest -q -m "not lean and not llm"

    Why not just -m "not lean"? The default -m 'not llm' in pyproject.toml is replaced (not combined) when you pass your own -m, so -m "not lean" would quietly run the real Claude test too.

  4. Make one real call through the CLI backend (about 5 seconds, uses a little of your Claude quota):

    uv run pytest -q -m llm tests/test_llm.py

  5. Optional: if you have an API key, try the API backend too. The key lives only in this terminal session:

    export ANTHROPIC_API_KEY="sk-ant-..."
MATHFINDER_LLM=api uv run pytest -q -m llm tests/test_llm.py

    VAR=value command sets a variable for that one command only.

Checkpoint

Ask Claude for a Lean proof, as JSON:

uv run python -c "
from mathfinder.llm import complete_json
print(complete_json('You are a Lean 4 + Mathlib expert. Answer with JSON only.',
  'Give a one-line Lean 4 tactic proof for: (a b : ℝ) : a ^ 2 + b ^ 2 ≥ 2 * a * b. Reply as {\"tactic\": \"...\"}'))
"

Expected (the exact tactic may differ):

{'tactic': 'nlinarith [sq_nonneg (a - b)]'}

Common errors

  • LLMError: claude CLI failed: ... not logged in: run claude once interactively and log in.
  • FileNotFoundError: 'claude': the CLI isn't installed or not on your PATH (Chapter 0, step 4).
  • anthropic.AuthenticationError with MATHFINDER_LLM=api: the key is missing or wrong in this terminal. Run the export again.
  • unknown MATHFINDER_LLM='API': names are lowercase (cli or api).
