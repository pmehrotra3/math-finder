M4c: The search loop and the command line

What and why. We now have all the pieces: a hammer, a planner, a critic and a prover. search.py runs them in a loop: (0) maybe automation proves the whole theorem; (1) the planner proposes plans; (2) the critic drops the ones that don't fit together; (3) the rest are tried cheapest first (fewest lemmas), each lemma going to the prover; (4) a plan with every lemma proved is assembled into one file and gets the strict final check; (5) everything that went wrong becomes feedback for the next round of planning. That last step is what makes it a search and not a lottery: each round knows which ideas failed and why. Finally, a command line lets you run it from the terminal.

Events

The search never prints anything itself. It reports what happens as events, small dictionaries like {"kind": "lemma_proved", "name": "odd_sum", ...}, passed to an on_event function you supply. The command line prints them; later the website will stream the same events to your browser, and the trace logger will save them for training. One search, many watchers.

Lean allows a namespace to stay open at the end of a file, so the candidates that follow are inside it too and can use the lemmas by their short names.

    What changed: test_preamble_uses_real_proofs_when_known expects the namespace MathFinder line, and checks that no earlier lemmas means an empty preamble.

  3. Create the search.

    {{file:mathfinder/search.py@m4c}}

    assemble writes the final file: every lemma with its real proof, then theorem main, all inside namespace MathFinder. That's why the final check asks about MathFinder.main, the theorem's full name.

    score is the fraction of a plan's lemmas that got proved, used to remember the closest plan. A refuted lemma means the plan's idea is wrong, so it scores -1.

    summarize turns a failed plan into text for the planner: each lemma with its status (PROVED / REFUTED / STUCK) and the reason. feedback[-6:] sends only the six most recent summaries, so the prompt doesn't grow forever.

    emit is a function defined inside search (a closure): it can use on_event from the enclosing function. **data collects keyword arguments into a dictionary, so emit("round", number=1) sends {"kind": "round", "number": 1}.

    sorted(fitting, key=lambda p: len(p.lemmas)) is the simple form of best-first search: try the plan that looks cheapest first. A lambda is a tiny unnamed function. SearchResult | None in a type hint means "a SearchResult, or nothing".

  4. Create the command line.

Checkpoint

The command from the last step printed this for us (about 40 s; your plans will be worded differently):

— round 1: asking the planner —
  ✗ plan doesn't fit together: Use Mathlib's telescoping principle Finset.sum_range_induction ...
      Application type mismatch: The argument
  fun k => odd_step k ...
  ▶ plan: Induct on n. The base case is trivial. In the successor case, peel off the last term
          with Finset.sum_range_succ, rewrite with the induction hypothesis, and close with ring.  (lemmas: none)

✓ VERIFIED by Lean. Plan: Induct on n. ...

namespace MathFinder

theorem main (n : ℕ) : ∑ i ∈ Finset.range n, (2 * i + 1) = n ^ 2 := by
  induction n with
  | zero => simp
  | succ k ih =>
    rw [Finset.sum_range_succ, ih]
    ring

end MathFinder


Result: PROVED (verified)

Look at what happened: the critic caught a broken plan in one Lean run, before any time went into proving its lemmas, and the second plan went through.

A false statement stops immediately, with no planning at all:

uv run python -m mathfinder prove --lean "(n : ℕ) : n ^ 2 ≤ 2 * n + 3"
Theorem: (n : ℕ) : n ^ 2 ≤ 2 * n + 3
✗ The statement is FALSE. Counterexample: n := 4; issue: 16 ≤ 11 does not hold

Result: not proved (the statement is false: n := 4; issue: 16 ≤ 11 does not hold)

Common errors

  • error: the following arguments are required: --lean: LaTeX input arrives in M5; for now give the Lean statement.
  • Your shell mangles ∑ or ℕ: always put the statement in double quotes. You can also write Nat instead of ℕ.
  • Every plan fails the final check with unknown constant 'MathFinder.main': your assemble is missing the namespace MathFinder / end MathFinder lines.
